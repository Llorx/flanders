# `implement` Command Contract — Workspace

## Purpose
Define what the `implement` command adds to the shared task workspace. The workspace itself — the main temporary folder, the per-reviewer folders, the per-iteration logs and the briefing `error.log`, the cleanup and the hard-stop preservation, the materialized per-iteration error logs, and the build and test script detection — is the shared workspace of [.spec/contracts/shared/task-workspace.md](/.spec/contracts/shared/task-workspace.md), set up at the start of every run before the first task is picked.

## Consolidated reference content
On top of the shared contents, the command writes one `spec.md` per agent that reads reference content: the worker's, in the main temporary folder, and each reviewer's, in that reviewer's own folder. Each holds the consolidated content of the contracts and rules the current task references, written per [src/commands/.spec/rules/ai/task-context.md#the-workers-first-iteration-receives-the-task-and-reference-content-by-deterministic-script-injection](/src/commands/.spec/rules/ai/task-context.md#the-workers-first-iteration-receives-the-task-and-reference-content-by-deterministic-script-injection) and [src/commands/.spec/rules/ai/task-context.md#every-reviewer-invocation-is-fresh-and-receives-the-deterministic-script-injection](/src/commands/.spec/rules/ai/task-context.md#every-reviewer-invocation-is-fresh-and-receives-the-deterministic-script-injection). A reviewer's folder holds that reviewer's `spec.md` and no other reviewer's, exactly as it holds only its own verdict file. These files are preserved and removed with the folders that hold them.
